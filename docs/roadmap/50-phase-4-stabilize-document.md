## 4. 기술 상세

이 Phase는 새 기능을 만들지 않는다. **이미 구현된 방어 장치를 실측으로 실증하고, 이미 측정한 수치를 신뢰 가능한 형태로 포장하는 단계다.**

### 4.1 장애 시나리오는 §7.13의 검증 항목을 그대로 실행한다

§5-7의 "키 없음 → Pull 폴백"은 개별 캐시 미스의 답이고, 전면 장애의 답은 §7.13의 방어 4종이다. Phase 2a에서 구현한 것을 여기서 처음으로 **전면 장애 조건에서** 검증한다.

- **F1(SHUTDOWN)**: 검증 대상은 "폴백이 있다"가 아니라 "폴백이 몰려도 버틴다". 세마포어 20을 넘는 요청이 부분 결과 대신 503 + `Retry-After: 1`로 거절되는지(§6 과부하 응답), 그 동안 DB가 살아있는지를 잰다. 부하 조건은 M3와 동일한 open model 주입을 기본으로 하되, 8GB 경합으로 하향 시 조건을 리포트에 기록한다(§9.3의 한계 명시 원칙).
- **F2(재충전)**: 별도 복구 작업이 없어야 한다는 것이 설계의 주장이다 — 축출/유실된 타임라인은 폴백의 최근 100개 Pull로 자연 복구된다(§5-5, §7.6이 §7.13에 흡수된 구조). 복구 시간의 판정 기준을 사전 고정하지 않으면 3회 반복값이 흔들리므로 4-01에서 프로토콜로 못 박는다.
- **F3(락)**: `timeline:lock:{userId}` (`SET NX EX 10`)이 동일 키 중복 폴백을 막는지, 동시 100건에서 Pull 쿼리가 몇 번 실행되는지를 센다. 서버 사이드 계측(§9.3)의 연장으로 Micrometer 카운터를 쓴다.

### 4.2 DB 커넥션 고갈과 Circuit Breaker (§7.13)

세마포어 20이라는 숫자의 근거가 "커넥션 풀 연동"이므로, 검증도 그 형태여야 한다. **세마포어가 없을 때 실제로 풀이 고갈되어 정상 경로까지 죽는가(F4-a), 있을 때 정상 경로가 사는가(F4-b)** — 대조가 있어야 장치의 존재 이유가 수치로 남는다. Circuit Breaker는 방향이 핵심이다: Redis 보호가 아니라 **DB 보호** — 폴백 실패율 초과 시 open되어 폴백 시도 자체를 차단하고 즉시 503을 반환하는지(open 구간 DB 쿼리 ≈ 0), 회복 시 half-open을 거쳐 닫히는지를 상태 전이 로그로 남긴다.

### 4.3 Grafana 대시보드 (§3 `bench` 프로파일)

모니터링은 상시 구동하지 않는다(§3) — 대시보드는 `bench` 프로파일 전용이고, Phase 3에서는 내려간다. 지표 소스는 기존 스택(Actuator + Micrometer + Prometheus) 범위를 벗어나지 않는다. 대시보드의 존재 이유는 두 가지: W10 장애 실험의 관측 도구, 그리고 §9.3의 "클라이언트 지연 − 서버 내부 지연 = 큐잉"을 눈으로 보이게 하는 것. JSON을 커밋해 재현 가능하게 한다.

### 4.4 성능 리포트와 재현성 (§9.6, §9.7)

"면접관은 그 규모로 쟀는지 검증할 수 없다 — 검증 가능성이 곧 신뢰도다." 이 Phase에서 그 요건을 전부 닫는다: §9.7 템플릿 통일(`docs/perf/m0.md`~`m3.md`), 원시 k6 JSON 커밋, 측정 환경 고정 서식, `make` 한 명령 체인, git 태그. 특히 M1 리포트의 "인덱스만으로 충분하지 않았던 이유" 절은 README 서술 원칙(실패한 시도를 적으려면 실패의 수치가 있어야 한다, §10)의 유일한 원료이므로 빈칸을 허용하지 않는다.

### 4.5 README (§10)와 12주 완결의 경계

README는 §10의 목차를 그대로 따른다: 한 줄 소개 / 차별점 4줄 / 아키텍처 / 기술적 도전 5건 / 측정 방법 / 일반화 / 의도적으로 하지 않은 것 / 실행 방법. 단, 12주 시점에는 Hybrid(M4)와 Kafka가 미구현이므로 **해당 서술은 "설계 완료·Phase 3 측정 예정"으로 정직하게 구분한다.** §8의 Phase 4″(문서 갱신)가 존재하는 이유가 이것이다 — Phase 3 완료 후 같은 목차 위에 M4 수치와 임계치 비교(500/5,000/20,000)를 덧쓴다. 도전 5건 중 ⑤(Sorted Set의 연쇄 인과)는 멱등성 실증(§7.3, Phase 2b의 중단·재처리 테스트)까지가 12주 범위의 근거이고, 파티션 키 결론은 설계 서술로 남긴다.

### 4.6 §11 점검 (§12 "답 없이 구현만 함"의 대응)

§11 표는 이 프로젝트의 완성 판정 기준이다. 4-17에서 근거 열을 산출물 경로로 채우는 행위 자체가 "빈 칸 = 남은 일"을 청산하는 마지막 작업이며, Phase 3 의존 행을 명시적으로 남겨두는 것이 12주 산출물의 정직성을 지킨다.
