# 00. 로드맵 개요 — 관제탑

> 전체 로드맵의 진입점. 각 Phase의 실행 상세는 개별 문서(→ [§6 문서 안내](#6-문서-안내))에 있다.
> 이 문서는 일정·마일스톤·의존 관계·중단 시나리오·진행 현황만 관리한다.

| 항목 | 내용 |

| 전체 기간 | **W1~W16 (2026-08-24 ~ 2026-12-13)** |
| 12주 완결·제출 가능 지점 | **W12 종료 (2026-11-15)** — Phase 4′ 완료 시점 |

## 2. 마일스톤과 측정 지점 (마스터 §9.2)

측정 지점 M0~M4는 변수를 하나씩 통제해 **개선의 귀속**을 가능하게 하는 장치다.
아래 주차는 Phase 기간 안에서의 배치 계획이며, 조건 정의는 마스터 §9.2가 원본이다.

| 마일스톤 | 조건 | 목적 | Phase | 주차 | 날짜 (해당 주) |
|---|---|---|---|---|---|
| **M0** | Pull, 인덱스 없음 | 최악 baseline | Phase 1 | W5 | 2026-09-21 ~ 09-27 |
| **M1** | Pull + 복합 인덱스 | "인덱스만으로는 한계"의 유일한 증거 | Phase 1 | W5 | 2026-09-21 ~ 09-27 |
| **M2** | Push, cold 캐시 | 폴백 경로 비용 | Phase 2a | W7 | 2026-10-05 ~ 10-11 |
| **M3** | Push, warm 캐시 | 본 성능 (p99 200ms / RPS 1,000 목표 검증) | Phase 2a | W7 | 2026-10-05 ~ 10-11 |
| 재측정 | Phase 2b 쟁점 반영 후 M3 조건 재확인 | 쟁점 구현이 성능에 준 영향 확인 | Phase 2b | W9 | 2026-10-19 ~ 10-25 |
| **M4** | Hybrid (임계치 5,000) | 머지 비용 | Phase 3 | W15 | 2026-11-30 ~ 12-06 |
| 임계치 비교 | 500 / 5,000 / 20,000 3종 | 양방향 트레이드오프 수치화 (§7.2) | Phase 3 | W15 | 2026-11-30 ~ 12-06 |

측정 공통 규약(모든 M에 적용, 마스터 §9.1/§9.3):
- **open model** (ramping-arrival-rate 포화 탐색 + constant-arrival-rate SLO 검증). `dropped_iterations ≠ 0`이면 그 측정은 폐기
- 혼합 시나리오는 조회 98% : 작성 2% (읽기:쓰기 50:1 가정, §7.1). fan-out 지연은 별도 단독 시나리오
- 3회 반복 중앙값 + 편차 병기, 코호트(`light`/`normal`/`heavy` 5,000명 풀) 고정, 원시 k6 결과 커밋

## 3. 의존 그래프

```
Phase 0 ──▶ Phase 1 ──▶ Phase 2a ──▶ Phase 2b ──▶ Phase 4′ ═══ [W12: 제출 가능 완결점]
 (기반)    (데이터+M0/M1) (Push+M2/M3)  (쟁점+검증)      │
                                                        └─(보너스)─▶ Phase 3 ──▶ Phase 4″
                                                                    (Kafka+Hybrid+M4)  (문서 갱신)
```

**각 화살표가 성립하는 이유**

| 선행 → 후행 | 이유 |
|---|---|
| 0 → 1 | 스키마·API·self-follow·Snowflake 팩토리가 있어야 더미 생성과 부하 시나리오가 성립한다 |
| 1 → 2a | **M0/M1 수치가 없으면 Push 전환의 동기("인덱스만으로는 한계")를 증명할 수 없다** (§9.2) |
| 2a → 2b | Push 경로가 있어야 Read-Your-Own-Write·백필·동등성 검증의 대상이 존재한다 |
| 2b → 4′ | 동등성 검증(불일치율 0%)과 재측정이 끝나야 리포트에 쓸 숫자가 확정된다 |
| 4′ → 3 | 아래 참조 — 문서화가 Phase 3보다 앞이다 |
| 3 → 4″ | Phase 3의 M4·임계치 비교 결과가 있어야 문서 갱신이 가능하다 |

**왜 문서화(4′)가 Phase 3보다 앞인가** (마스터 §8 "일정 구조" 재서술)

마스터 §12의 첫 번째 리스크는 **완주 실패**이고, 그 대응은 "Phase 2까지만 해도 충분하다"이다.
이 판단이 실제로 작동하려면 일정 구조에 반영되어야 한다. README와 성능 리포트를 맨 끝에 두면
중단했을 때 남는 것이 **코드뿐인 상태**가 된다. 문서화를 12주 안(Phase 4′)에 넣으면 W12 시점에
**항상 제출 가능한 완결 산출물**이 존재하고, Phase 3(Kafka + Hybrid)는 그 위에 얹는 보너스가 된다.

## 4. 중단 시나리오 — 어느 시점에 멈춰도 무엇이 남는가

| 중단 시점 | 완료된 Phase | 남는 산출물 | 제출 가능? |
|---|---|---|---|
| **W5 종료** (2026-09-27) | 0, 1 | 전 기능 + 300만 건 데이터 + M0/M1 원시 결과 + EXPLAIN ANALYZE 병목 분석 | **부적합.** "인덱스 설계" 단편만 있고 캐시 개선 서사가 없다. 포트폴리오로 내세울 개선 폭이 없는 상태 |
| **W7 종료** (2026-10-11) | 0, 1, 2a | + Push 타임라인 + §7.13 스탬피드 방어 + M2/M3 → **"Pull → Push로 p99를 개선했다"는 완결 서사 하나 성립** (마스터 §8 Phase 2a 완료 조건) | **가능 (단, README·아키텍처 다이어그램 미완 — 공개 전 문서화 기간 필요).** m2/m3 리포트와 수치는 W7 안에 완성되므로(30 문서 T9~T10) 미완은 README·다이어그램뿐이다 |
| **W9 종료** (2026-10-25) | 0, 1, 2a, 2b | + 필수 쟁점 구현(§7.7/7.8/7.9/7.5/7.4) + 동등성 검증 CI(불일치율 지표) + Virtual Thread 실험 + 재측정 | **조건부 가능.** 내용은 충분하나 W7과 같은 이유로 문서화가 남는다 |
| **W12 종료** (2026-11-15) | 0, 1, 2a, 2b, 4′ | + 장애 시나리오 실측(Redis SHUTDOWN) + README/아키텍처 다이어그램/성능 리포트 + 원시 k6 결과 + git 태그 | **가능.** 계획된 완결 지점. 이후 Phase 3·4″는 순수 보너스 |

> 이 표가 말하는 것: **문서화 이전 중단(W5/W7/W9)은 항상 "정리 부채"를 남긴다.**
> 그래서 4′가 3보다 앞이고, W12 이후에는 언제 멈춰도 손실이 없다.

## 6. 운영 원칙

### 6.1 측정 없이 다음 Phase로 넘어가지 않는다

**M0~M4가 Phase의 관문이다** (마스터 §12). 각 Phase 종료 조건에 해당 측정이 포함되며,
측정이 없으면 그 Phase는 "완료"가 아니다. `dropped_iterations ≠ 0`인 측정은 무효이므로 관문 통과로 치지 않는다(§9.1).

- Phase 1 관문: M0 + M1 기록 (`docs/perf/m0.md`, `m1.md`)
- Phase 2a 관문: M2 + M3 기록
- Phase 2b 관문: 재측정 + 동등성 검증(불일치율 0%) CI 통과
- Phase 3 관문: M4 + 임계치 3종 비교 기록

### 6.2 리스크 요약 (마스터 §12 — 원본이 우선)

| 리스크 | 대응 (이 로드맵에서의 반영) |
|---|---|
| **완주 실패 (최대 위험)** | 문서화를 W12 안(Phase 4′)에 배치. Phase 3·4″는 보너스 → §3, §4 |
| 로컬 리소스 8GB | Compose 프로파일 3종(`dev`/`bench`/`async`). Phase 3에서 모니터링 내림 |
| 측정치 오염 | 게시글 300만(buffer pool 1G 내). 히트율 95% 미만이면 200만으로 하향 후 기록 |
| 기능 추가 욕심 | 댓글·해시태그·검색·DM·차단·게시글 수정 전부 금지 |
| 측정 없이 개발만 함 | §6.1의 M 체크포인트 관문 |
| 측정을 했는데 신뢰 불가 | open model + 변수 통제 + 3회 반복 + 원시 결과 커밋 (§9) |
| 빠른데 틀림 | Pull==Push 동등성 검증 CI 편입, 불일치율을 성능과 나란히 기록 (§9.4) |
| 쟁점 과다 착수 | [필수] 4개(§7.3/7.7/7.8/7.13) 우선. §7.10/7.12는 하지 않는다 |
| 답 없이 구현만 함 | 아래 §6.3 |

### 6.3 §11 근거 열이 비어 있으면 그게 남은 일이다

마스터 §11(면접 예상 질문)의 각 질문에는 근거 위치(설계 절 + 측정)가 매핑되어 있다.
**Phase를 마칠 때마다 §11을 열어 해당 Phase가 채웠어야 할 근거 열이 실제로 채워졌는지 확인한다.**
비어 있는 열은 백로그이며, 그것이 채워지기 전에는 해당 서사를 README에 쓸 수 없다.
(예: "이 구조에서 랭킹 기반 피드로 바꾸려면?"은 마스터에서 미작성으로 남긴 항목 — Phase 4′ 문서화 때 판단한다.)
